Aprendizaje de Django

Es un framework para realizar aplicaciones web usando la tecnología Python.

Primer paso comprobar si esta dentro de nuestro sistema o entorno virtual  o no usando el siguiente comando:
    python -m django --version

Segundo una vez comprobado que no existe lo añadimos teniendo en cuenta el nombre del directio donde esta almacenado
mi projecto donde pensaremos otro nombre y el siguiente comando:

	django-admin startproject name_project name_directory

Que generara dentro del directorio que nombramos la carpeta del projecto y el archivo manage.py.El archivo manage.py
actúa como una interfaz de línea de comandos que permite a los desarrolladores interactuar con el proyecto y ejecutar
diversas tareas de administración además de la carpeta del projecto que tiene los siguientes ficheros:
1. __init__.py --> este archivo esta para identificarse como un paquete de python
2. settings.py --> este archivo esta para la configuración del projecto
3. urls.py --> este archivo esta para declarar las url
4. asgi.py --> este archivo este como punto de entrada para servidores web ASGI
5. wsgi.py --> este archivo este como punto de entrada para servidores web WSGI


Diferencia entre una aplicación y un proyecto

Cada aplicación es una aplicación web que hace algo mientras que un projecto 
es una colección de configuración y aplicaciones para una web particular.
Un projecto puede contener muchas aplicaciones

Cuarto paso crear una aplicación usando el siguiente comando:

python manage.py startapp name-app

Una vez creado tiene los siguientes ficheros :

1. admin.py --> este archivo esta para la configuración del projecto
2. apps.py
3. models.py --> para definir los modelos de datos 
4. tests.py --> para definir pruebas unitarias,de integración,CI&CD
5. urls.py  --> definición de las urls dentro de la aplicación
6. views.py --> definición de las vistas HTML,CSS(lo visual)

Y tiene un directorio para migraciones con el documento __init__.py para identificarse como un 
paquete de python


Configuración de la BD

/nombre-projecto/settings
1- Por defecto se usa SQLITE 
2- Establecer zona horario con el parámetro TIME_ZONE
3- INSTALLED_APPS es el parámetro para añadir todas las aplicaciones activas dentro de la instancia de
   Django
	3-1 django.contrib.admin --> sitio de administrador
	3-2 django.contrib.auth --> sistema de autenticación
	3-3 django.contrib.contenttypes --> framework para tipo de contenido
	3-4 djnago.contrib.sessiones --> framework de seciones
	3-5 django.contrib.messages --> framework de mensajería
	3-6 django.contrib.staticfiles --> framework para manejar ficheros estáticos

4- Para actualizar los modelos de la base de datos usamos el siguiente comando

	python manage.py makemigrations name-app
	
	Aquí es como decirle He hecho cambio a mis modelos y que le gustaría que lo guarde como una migración
	En el caso en que no sepas que es una migración son la forma en la que django almacena los cambios en
	tus  modelos (y, por lo tanto, en el esquema de tu base de datos);son archivos en el disco.Si lo 
	deseas puedes leer la migración de tu nuevo modelo; es el archivo name_app/migrations/0001_initial.py.
	No te preocupes no se espera que lo leas cada vez que Django crea uno pero están diseñados para que
	puedan ser editados por humanos en caso de que quieras modificar manualmente los cambios que Django
	realiza.
	Comando para las migraciones es migrate
	Toma todas las migraciones que no han sido aplicadas rastreándolas usando una tabla especial llamada django_migrations
	y lo ejecuta contra su BD,basicamente,sincronizando los cambios que usted ha realizado a sus modelos con el esquema de la BD
5- 
	5.1 - La salida exacta depende de la BD
	5.2 - Los nombres de las tablas se genera automáticamente combinando el nombre de la aplicación y el nombre del modelo
	Convención: los nombres de los modelos van en mayusucula
	5.3 - Las claves primarias (ids) se agregan automáticamente.
	5.4 - Convencionalmente Django añade "_id" al nombre del campo de la clave externa
	5.5 - La relación de clave externa se hace explicita mediante una restricción FOREIGN_KEY 
	5.6 - Esta adaptado a la BD que estas utilizando por lo que los tipos de campos especificados de la base de datos se gestionan automáticamente.
	      Lo mismo hace con las doble comillas en los nombres de los campos
	
	Los comandos migrate y makemigrations están separado por tema de control de versiones

6- Para saber si hay problemas  se puede ejecutar el siguiente comando python manage.py check este comando revisa cualquier problema sin hacer migraciones ni modificaciones en la BD
